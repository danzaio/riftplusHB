The AIO grows from the way you actually play.

Every feature starts with a player request. The community decides what earns a place in the next release.

  1. 01

    Submit

    Point to a champion and a feature, then describe what should change.

  2. 02

    Curate

    Requests are checked for scope, safety, and a clear runtime contract.

  3. 03

    Vote

    When a request is ready, players vote yes on the exact behavior they want.

  4. 04

    Ship

    When yes reaches the threshold, the feature enters the next AIO release queue automatically.

THE SHARED CORE

One contract. Champion logic stays distinct.

Shared infrastructure handles documented runtime contracts. Combat identity remains inside each champion.

  1. 01

    Documented SDK

    Shared helpers follow documented object, Prediction, damage, and callback contracts.

  2. 02

    Champion Logic

    Spells, ranges, priorities, and combat state stay isolated per champion.

  3. 03

    Fail-closed Safety

    Unsupported identifiers and unsafe routes are rejected instead of guessed.
